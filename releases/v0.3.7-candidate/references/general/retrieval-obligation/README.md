# Retrieval Obligation 0.5 — Optional Reference

Status: `v0.3.7 candidate.2 / GENERAL_OPTIONAL_REFERENCE / DEFAULT_OFF / NOT_NORMATIVE_ONTOLOGY`

Use when a consequential decision depends on retrieval scope, the effective content actually returned, freshness, or sufficiency closure.

Do not invoke merely because durable knowledge exists, and do not interpret a `HIT` as sufficient discovery.

Bundled machine files are the selected Retrieval Obligation 0.5 research reference bytes. The candidate packages them as a reusable HOW; it does not promote their schema vocabulary into universal ENA law.

Key boundary:

```text
KNOWN != RETRIEVED
HIT != SUFFICIENT
DECLARED_COMPLETE != COMPLETENESS_TRUE
REFERENCE_VALID != HOST_RESOLVER_TRUTH
```

The reference keeps effective result identity, decision-material freshness, logical resolver identity, bounded no-hit, and explicit unknown/completeness boundaries.

Host-native semantic search, exact-path lookup, scope registries, or other retrieval systems remain legitimate alternatives.

Machine PASS proves represented consistency only. Registry truth, content immutability, evaluator legitimacy, actual completeness, and natural invocation remain Host/evidence questions.
